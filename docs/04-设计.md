# 04 · 设计（V1）

> 状态：草案待确认。2026-08-02 查证后 ADR-005 需修订（见末尾）。

## 1. V1 架构（路线 A 纯配置型）

```
用户安装
  → fnOS install 向导填 PVE 地址/端口
  → install_callback 生成 nginx 透传配置
  → 应用启动，nginx 监听透传端口
  → FN Connect 穿透该端口（.sc port_forward=yes）
  → 用户打开链接 = 原版 PVE WebUI
```

- 应用本体：nginx 反代引擎（无管理界面）+ fnOS 原生向导 + 生命周期脚本
- 无自研长驻进程；配置走 fnOS 的 config 向导（config_callback 重写配置 + 重启）
- 应用中心「打开」按钮 → service_port = 透传端口 → 打开即 PVE WebUI

## 2. 透传配置模板（核心）

```nginx
server {
    listen       8800;                          # 透传端口（向导可改）
    server_name  _;
    location / {
        proxy_pass        https://192.168.8.10:8006;   # 向导填的 PVE 地址
        proxy_set_header  Host $host;                  # PVE 靠 Host 头拼 URL
        proxy_http_version 1.1;
        proxy_set_header  Upgrade $http_upgrade;       # noVNC/控制台/日志 = websocket
        proxy_set_header  Connection "upgrade";
        proxy_buffering   off;                         # 长连接必需
        client_max_body_size 0;                        # 上传 ISO/备份不设限
        proxy_connect_timeout 3600s;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
        proxy_ssl_verify  off;                         # PVE 自签证书，后端不校验证书
    }
}
```

依据：PVE 官方 wiki《Web Interface Via Nginx Proxy》（Tested 3.4–6.3）+ 论坛大量案例。
与 wiki 差异：wiki 场景是 PVE 本机装 nginx 用 PVE 证书；本项目 nginx 在飞牛上，证书由
FN Connect（fnos.net 域名）解决，后端 https→https 需 proxy_ssl_verify off。

```
pve-pilot/fnos/

```

## 4. 三个设计约束（查证结论）

1. **必须根路径透传**：PVE WebUI 硬编码根路径，不支持 /pve 子目录（官方论坛确认子目录资源 404）。
   反代用独立端口，不与飞牛 WebUI 的 80/443 路径冲突。
2. **Host 头必须透传**：pveproxy 按 Host 头生成链接（API 地址/noVNC 地址），改 Host 会登录后白屏/重定向循环。
3. **PVE 自签证书**：飞牛 nginx → PVE 8006 是 https→https，后端 proxy_ssl_verify off；
   浏览器→飞牛 这段走 FN Connect 的 fnos.net 证书，用户无告警。

## 6. ADR-005 修订（2026-08-02 确认）

原 ADR-005：应用不内置反代，依赖商店反代容器（nginx / NPM / nginx-ui），应用内检测 + 向导引导安装。

**修订为：内置反代引擎，不内置反代管理系统。**

查证结论（conversun/fnos-apps 仓库，2026-08-02）：

| 事实 | 影响 |
|:--|:--|
| 商店三个反代（nginx / nginx-ui / NPM）**全部是 conversun 第三方商店包**（manifest distributor=conversun），飞牛官方应用中心无反代应用 | 「商店现有反代」前提不成立 |
| nginx 应用是单文件 nginx.conf（无 conf.d） | 注入配置需侵入改写对方配置文件 |
| 配置在 `/var/apps/nginxserver/var/nginx.conf`（第三方包数据目录） | 跨应用写配置，升级/卸载即坏 |
| 应用 `daemon off` 前台跑，无 reload 路径 | 配置变更需重启对方应用，侵入感强 |
| FN Connect 穿透声明在各应用自己的 .sc | 依赖第三方反代则穿透端口受制于人 |

**决定：内置静态 nginx 引擎（~5MB，无管理界面）**
- 装即用，零依赖，不侵入第三方包
- 配置全在自己 var 目录，升级/卸载无耦合
- 自声明透传端口 .sc → FN Connect 直连
- 「内置反代引擎」≠「内置反代管理系统」：无 WebUI、无配置界面，只是引擎

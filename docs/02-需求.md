# 02 · 需求

## 版本规划

| 版本 | 内容 | 状态 |
|:--|:--|:--|
| **V1（MVP）** | PC 端通过 FN Connect 链接访问原版 PVE WebUI（内置反代引擎 + 配置向导 + 商店打包） | 规划中 |
| **V2** | 移动端界面（PVE API：节点状态 / VM 列表 / 电源操作）+ noVNC 控制台 | 规划中 |
| **V3+** | 快照/备份、多节点集群、通知推送、密码登录 | 远期 |

## V1（MVP）需求

### 目标

> 用户装应用 → 填 PVE 地址 → 得到可访问链接 → PC 打开是原版 WebUI

### 功能清单

| 模块 | 功能 | 说明 |
|:--|:--|:--|
| 配置向导 | PVE 地址 / 端口 / 透传端口 | 应用本体，中文界面 |
| 内置反代引擎 | 打包静态 nginx，生成透传配置 | 装即用，零依赖（ADR-005） |
| PC 透传 | 原版 PVE WebUI 完整透传 | 保留 PVE 自身认证（密码 / 2FA） |
| 穿透 | FN Connect 链接可用 | 应用声明端口（.sc port_forward） |
| 商店打包 | .fpk 发布 | fnpack / fnOS 应用格式 |

### 非目标（V1）

- 移动端界面（V2）
- PVE API 对接（V2）
- noVNC 控制台（V2）
- 多节点、备份、通知（V3+）

## V2 需求（预告，设计阶段细化）

- 设备识别分流：PC UA → 原版 WebUI；移动 UA → 移动端界面
- PVE API 网关（token 代理，隐藏真实 PVE 地址）
- 移动端功能：节点总览（CPU/内存/存储/网络）、VM/CT 列表（状态/资源/搜索）、电源操作（开关机/重启/暂停，二次确认）、noVNC 控制台
- 安全：API Token 认证、HTTPS 透传、防误触确认、操作日志

## 决策记录（ADR）

### ADR-001：认证方式 — API Token（V2）
- PVE API Token（`PVEAPIToken=user@realm!name=uuid`），权限可细粒度
- 比存密码安全：泄露可单独吊销，不影响 PVE 密码/2FA
- V1 不做（V1 走 PVE 自身认证）

### ADR-002：单节点优先
- V1/V2 单节点；集群支持 V3+

### ADR-003：noVNC 控制台排 V2
- 手机端 noVNC 体验一般（虚拟键盘/触控），实现复杂度高（websocket 代理）
- 第一版聚焦「看状态 + 电源操作」高频需求

### ADR-004：界面语言
- 第一版中文界面（飞牛社区），代码 i18n 架构预留英文

### ADR-005：内置反代引擎（2026-08-02 修订）
- ~~应用不内置反代，依赖商店现有反代容器~~ → 已废弃
- 修订：内置静态 nginx 引擎（~5MB，无管理界面），配置全在自己 var 目录
- 依据：商店三个反代（nginx / nginx-ui / NPM）全部是 conversun 第三方商店包（非飞牛官方），
  且均需侵入式注入配置，依赖脆弱。详见 04-设计.md §6

## 用户故事

- 作为飞牛用户，我在外面用手机打开 FN Connect 链接 → 看到原版 PVE WebUI → 完成紧急管理操作（V1）
- 作为飞牛用户，我在手机上打开链接 → 看到 PVE 管家移动界面 → 快速查看 VM 状态/开关机（V2）
- 作为飞牛用户，我用电脑访问同一链接 → 看到原版 PVE WebUI，与本地操作无差异（V1）
